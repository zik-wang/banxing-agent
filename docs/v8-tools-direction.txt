伴行V8：通用工具与模型编排
批准依据：用户要求保留现版、建立新版本，以tools实现底层调用，让模型组合工具链；Harness承载工具基础设施。

问题定位
V7已有工具调用循环，并非完全没有tools；runtime.mjs还承担场景推断、Office专用计划、发票直达、固定读取顺序和业务兜底。V8要降低这些业务路由与通用执行层的耦合，复用经验证的工具能力。
不将旧的复杂场景处理器简单改名为tool就宣称架构完成。

责任边界
模型：理解目标、挑选工具、决定后续步骤、处理语义不确定性、组织结果。不能自行登记工具成功、放大授权范围或宣布未检查材料完整。
工具：明确输入、实际动作、输出结构、错误类型、能力限制和来源；例如表格合并须指定业务键，不猜测删除重复行。
Harness：工具注册表、参数/输出校验、调用ID、附件作用域、调用循环、取消/超时、预算、持久化结果、恢复、缓存以及最终交付凭据。具体模型与传输协议通过适配器接入。
MCP：可选传输/发现适配层。本地与MCP入口共用工具实现和契约；MCP接入不是准确率声明。

第一批工具能力
- materials.list / materials.inspect：枚举授权材料、哈希、格式、页数/工作表目录、解析状态。
- document.read_text / document.render_page：指定范围读取文本或实际页面，显式返回分页游标、截断与来源。
- vision.extract / ocr.extract：对指定页/区域实际识别，保留输入图哈希、原始响应、finish_reason、不确定项及覆盖信息。
- spreadsheet.read_range / spreadsheet.transform：精确范围读取和确定性变换；原始记录、去重键、行数变化可追溯。
- compute：受约束的确定性计算能力。任意代码执行如果后续需要，必须单独设计执行隔离，不能默认继承全部机器权限。
- artifacts.create / artifacts.inspect：生成有下载凭据的产物，再实际回读文件结构/内容；不靠模型宣称已导出。
这些是待实现/迁移的能力规划，名称并非已经注册可用的工具列表。

工具约定
每个工具声明name、version、description、inputSchema、outputSchema、作用域、read/write副作用和执行限制。
回执保留callId、toolVersion、输入引用/哈希、status、data或resultRef、coverage、warnings、error、耗时以及产物引用。
“调用完成”与“内容完整/正确”分开。解析失败、部分结果和未确认值不伪装成ok。
大结果先落盘/持久化，模型按页或游标取用；不能静默截断。模型上下文中的摘要不能替代原始结果。
缓存键覆盖文件版本、页码、区域、任务目标/schema与引擎配置；失败重试留存attemptId，不能拿同文件第一次回答覆盖不同页。
读文件等幂等操作可有界重试；写入工具需要去重/幂等语义与实际回读，不自动重放未知结果的写操作。

通用运行流程
用户目标及授权材料 -> 模型获得相关工具描述 -> 模型提出工具调用 -> Harness校验并执行 -> 保存真实回执 -> 模型依据回执继续 -> 检查任务范围/交付凭据 -> 输出结果及未完成项。
不存在必须先命中18或28场景之一的条件；超出已注册能力时明确缺少什么工具。
可以批处理确定的文件列表与页面清单；文件/页面枚举、状态计数及缺失范围由程序负责。

迁移顺序
1. 提取/复用已有模型适配器与工具循环，新增独立V8入口及数据目录；V7入口留作对照，不改开发侧运行进程。
2. 为实际文件读取、表格范围、计算、产物生成建立小规模通用工具集和合同测试；先验证一条真实工具链。
3. 接入指定页/区域视觉与OCR，保留已知WHO失败样本；逐页覆盖与识别质量分别验收。
4. 让模型处理未预设的新任务，评估选工具、参数、过程恢复及交付是否可靠，再逐步扩展工具集。
5. 有多进程复用需求时添加MCP适配，不复制第二套业务逻辑。

验收
- 真实材料：沿用WHO156页PDF、场景15原PDF、真实表格；新增未预设任务进行留出测试。
- 泛化：任务不在场景枚举中仍可组合现有工具；缺工具时如实说明，不谎称完成。
- 工具正确性：输入范围、页码/行数、计算、导出文件及读回结果各自核验。
- 编排正确性：多文件来源隔离、异常恢复、调用预算、分页和结果完整性。
- 识别质量：人工标注样本上的字段正确率/召回、实际缺失行、重复输出；调用成功不算识别通过。
- 新版本演示必须来自独立V8入口与独立状态；继承V7界面或只修改名称不算完成。

与之前方案的关系
multifile-vision-harness-mcp-plan.txt中的页级证据、缓存、恢复和质量回执转为通用工具能力及Harness约束；不再把每个业务场景的完整流程写入核心。
当前V7修复与验收独立继续，未通过项目不能因为创建V8而自动关闭。
