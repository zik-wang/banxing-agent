# 可加载合同审核配置候选

继续使用现有 WebWorkspace、审核助理和原件/成果权限；没有新增演示应用。部署配置显式设置 `contractReview.reviewEngine: "profile-v3"` 使用新流程。未设置时保留旧流程，用于历史兼容和对照；不在运行中修改8884。

```json
{"contractReview":{"enabled":true,"reviewEngine":"profile-v3","maxCalls":12,"maxTokens":6000,"maxBatchChars":9000,"maxContextChars":60000,"timeoutMs":900000,"localReview":{"enabled":false},"botIds":["review"]}}
```

`botIds` 是维护者配置的能力绑定，不从可编辑 Skill 文本推导授权。用户指导不会改变工具、地区门禁、外发授权或模型预算。新助理只有被维护者加入该集合才能进入专项。

临时外发授权在每次调用前重新检查有效期；企业政策重新核对已批准哈希。自定义审核配置也须单独批准内容哈希，否则仅在内网使用。聊天指导或更换合同类型不会自动扩大这些授权。本轮真实测试只用内网；公网门禁用明确标注的离线合成测试核验。

`contract-review/profiles/` 有设备采购16项、服务8项、基础文本6项。每项包括触发、保障/例外、后果、可接受替代和正反例。未知类型只用明确标记的基础核查；地区不匹配不默默套用。新增配置不复制核心流程。`reviewProfileFile`、`policyFile` 只能由维护者配置。

新模型协议及JSON Schema见 `compact-protocol.mjs` 和 `schemas-v3.json`。模型提交单元ID与原文短句；宿主唯一匹配Unicode跨度。引文不存在或重复时隔离坏项，保留原始候选及其他有效发现。宿主记录发送、处置和未处理范围；模型声明完成不证明理解正确。旧 `contract-submit-2` 及其读取/导出路径保留。

基础审查每批一次，覆盖该配置的全部专题，之后才汇合程序、可选本地模型和已启用反馈候选。跨条款及反例预算提前规划，格式恢复不能侵占必需的后续阶段。超预算仍保留文件、发现和未完成目标，不提高调用上限或用导出掩盖partial。

长材料先全部进入基础批次。跨条款和反例在上下文可容纳时读取全部原文，否则选取候选位置、相邻单元及全局保障/例外条款；保存未选范围。此检索会漏语义变体，不宣称全文反例穷尽。相关原文仍超预算时明确保留未核，不能截成片段宣称完成。

本地1.5B是可选候选插件，纯27B不依赖权重或本机训练环境。27B先独立审查；本地独有候选随后得到有证据的supported/not_supported/uncertain处置。not_supported需要真实反证，候选不会删除；复用局部信号不当作第二次独立意见。关闭或失败会显式说明插件状态。反馈正反例命中只证明规则测试，不证明语义能力提升。

默认企业政策为空、法律检索未连接，报告如实标记；不生成法条或检索成功收据。所有比例、期限和替代条款均是业务建议，不作最终签署决定。没有独立Gold不发布准确率或模型超越结论。

候选由独立冻结目录和配置启动，正式8884及业务候选8914不切换。回退只需继续使用原地址，旧对话/原件/下载ID没有迁移或删除。
