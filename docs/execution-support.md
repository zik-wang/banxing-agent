# 持久执行状态与可恢复工具回执

`executionRepair: true` 的通用工具运行器默认启用执行支持。宿主可设置 `executionSupport: false` 关闭新增工具。此配置不改变模型、工具权限、来源范围、调用预算或合同专项协议。

## 工具

- `update_plan`：保存最多12个步骤，同一时刻最多一个进行中步骤。完成步骤必须引用当前执行范围内真实成功的业务工具callId。计划描述由模型提供，不代表事实或业务结果已独立核实。
- `get_execution_state`：取回持久计划、实际计数、已存草稿和成果引用；必填 `include_recent` 控制是否附带近期调用。它不把计划更新算成处理材料或交付文件。
- `read_tool_receipt`：按真实callId取回旧工具回执；支持RFC6901字段指针、字面查找和分页。压缩历史提供这个恢复入口，避免因为正文离开上下文而重新处理原件。

持久状态位于运行目录下 `execution-support/<scope-hash>/`。scope由宿主根据当前原始请求、材料ID/SHA和任务范围产生；模型不能传路径或变更scope。取回回执时检查内容摘要、当前原件版本和本地私密输出政策。历史回执不是一次新的来源核验。恢复的是计划和既有结果，不代表自动恢复整个模型会话或重放业务写入。

参数错误、缺正文、重复失败和不存在的工具会给出真实注册schema或当前可用工具名，让模型有明确的纠正依据。它不能增加工具能力或自行放宽schema。

计划和状态查询不会清除已有的重复证据边界；完成状态不能使用计划、发现工具或取回历史回执自身作业务证明。实际文件是否交付仍由保存、回读和交付结算决定。

## 验证

`tests/v8-execution-support.test.mjs` 覆盖重启后取回、分页、指针、伪造/跨任务/篡改拒绝、私密本地内容、完成证据、乐观版本、进展计数、实际schema反馈，以及模型循环的纠错路径。

同模型能力比较仍应固定硅基流动模型、原始请求、原件和预算，分别记录接口错误、实际工具轨迹、文件回读、业务内容、请求数和usage。定向工具探针不能冒充18场景盲测或整体能力评估。
