# T2 合同审核模型与财务协作补充实测

本次只补充实验依据，没有改变产品行为、部署版本或模型权重。原始运行证据保留在本机；本目录仅含允许分享的合成案例结果与脱敏摘要，不包含公司合同、录音、凭证或原始模型请求。

## 当前选择与结论边界

继续采用 27B 单 Agent 承担完整合同审核，金额环节使用确定性计算器。选择原因首先是完整审核任务能力；金额计算只是其中一环。本地 1.5B 的现有微调任务是风险类别初筛，不能据此替代全文审核。

此次增加了本地 1.5B 的两次真实 GPU 生成，以及真实网页财务转交实测。单个合成案例不足以证明整体模型优劣，也没有新增独立人工 Gold 或用户验收。财务协作的完整收益仍未证明。

## 同一合成大额案例

设备价款 1.25 亿元、安装费 360 万元、培训费 48,000 元，均需计入含税总额。预期为人民币 **128,648,000.00 元**。

- 历史 27B：实际 128,648,000.00 元，1 次请求，7,771 ms。
- 历史单 Agent 加计算器：实际 128,648,000.00 元，2 次请求，13,455 ms。
- 历史财务角色加计算器：实际 128,648,000.00 元，3 次请求，35,722 ms。这是宿主编排实验，不等同于真实自动转交验收。
- 新增本地 1.5B 原生协议：只输出支付与财务风险标签，不输出金额；不作为算术正确样本计分。
- 新增本地 1.5B 金额协议：实际 **125,000,000 元**，漏计安装与培训费 **3,648,000 元**；生成的计算计划未通过来源校验，不进行人工修补后宣称成功。

历史三组本轮没有重跑。1.5B 金额提示词由保留的实验代码重建，历史 27B 提示词未在调用前独立冻结，不能证明逐字一致；这是超出现有分类训练目标的探索，不是严格控制变量的模型排名。

## 模型与运行条件

- 本地：Qwen2.5-1.5B-Instruct + R2 LoRA，BF16，rank 8，q_proj/v_proj；RTX 4060 Laptop 8GB，Torch 2.6.0+cu124。
- 既有训练：240 步，验证选择 160 步；学习率 0.0001，seed 61102；训练/验证/测试样本数 231/37/66。此次没有重新训练。
- 原生推理：188 输入 token，greedy，max_new_tokens 96；实际输出 13 token，2.203 秒。
- 金额推理：328 输入 token，temperature 0.1，top_p 1，seed 61102，max_new_tokens 1400；实际输出 71 token，7.031 秒，未超时。
- 历史 API：硅基流动 `Qwen/Qwen3.8-27B`，temperature 0.1，max_tokens 1400，enable_thinking=false。
- 本轮生产链路 API：同一提供方与模型标识，max_tokens 8192，enable_thinking=false；其余未独立确认的服务端参数、量化和后端记为 unknown，不根据模型名称推断。

## 真实网页财务转交

使用同一合成材料和核算目标，从通用助理进入；对照请求分别明确要求自行核算或交给现有财务助理。因此验证的是用户提出转交后产品实际自动执行，不能宣称无提示自主路由。

- 单 Agent：实际调用 `calculate_money` 得到 128,648,000.00 元，但最终答复被 HTTP 429 阻断，任务没有完成。
- 财务转交：初次请求被 429 阻断；一次有界恢复后观察到真实 `request_assistant_handoff` 及财务 work 阶段。
- 财务 work 首次读取发生 `UNKNOWN_ASSET`，随后经发现工具、检查和读取恢复，增加了执行开销；之后又被 429 阻断。
- 最终 A 复核阶段没有执行，不标记为完整 A→B→A 成功，不把接口限流解释为金额计算错误。

本轮共新增本地生成 **2 次**，公网 HTTP 模型请求 **12 次**：200 为 9 次，429 为 3 次。已知 token 合计 **67,867**，另 3 个失败响应没有 usage；费用 unknown。没有通过更换模型掩盖失败，没有无限重试。
