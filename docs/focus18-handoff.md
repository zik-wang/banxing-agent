## Changes and evidence

- **V7-REAL28-002 (07/08/10):** A whole-request negative-word match incorrectly returned `selection`. The new selection predicate accepts standalone input-removal clauses; “don't delete originals” and other task constraints preserve the primary instruction. Original requests are regression fixtures without editing their wording. Genuine ordinal/named exclusion remains covered.
- **V7-REAL28-001 (03/04/11/13):** The text reader returned 5000 characters but no next offset or total, while upload previews could stop at 60000. Authorized original text is now read as a hash-checked view with explicit offsets and range coverage; 16000-character pages reduce redundant round trips. Release-array projection retains every version/date/body and declares omitted transport/asset metadata. It does not truncate release bodies. Input limit is explicit at 2MB, not an unbounded context increase. Model rounds remain unchanged.
- **V7-REAL28-003 (05):** A final answer could request a body without reading already-bound files. Complete text inputs up to a combined 8000 characters are included directly as untrusted source material; larger text gets an unread-range recovery instruction. Real mail now reaches the first model turn. Scope, original hash and access checks remain in place.
- **V7-REAL28-004 (09):** General chat directly exported a model-supplied invoice sheet; this path did not use the invoice handler's relation gates. A narrow export guard now checks card-expiry dates against their own native/OCR text field, rejects vision-only/service-date borrowing, retains an explicit blank/needs-confirmation field, and records issues before workbook generation. It is not a general proof of invoice correctness. Dedicated 09 handlers are unchanged.
- **01 / 15:** Source policy requires explicit event dates, no publication-date back-calculation, and unresolved parallel lists throughout the answer. OCR receipts expose grouped parallel fields. Real follow-ups preserve the two multi-application/vendor/date groups as unresolved, including later discussion. This is observed developer evidence, not a gold accuracy measurement.
- **07 recovery:** An existing >10-page OCR boundary caused repeated retries. Each file/reader now retains its successful or blocked receipt within the run; failures are not retried indefinitely. A readable native layer can support limited work with an explicit unverified-range notice. The OCR page cap was not raised; the larger PDF remains unverified by OCR.
- **10 delivery:** A model-written replacement sheet could alter historical cells. Structured XLSX input now uses the actual original workbook, maps reordered headers, preserves extra input fields, deduplicates on explicit business columns, checks every prior cell/value/style/merge and every new cell on readback, and records all dispositions. User-named template/key bindings fill omitted tool arguments only when unambiguous. Direct export cannot bypass this handler.
- **19 protection:** Generic source-code repair wording now reaches the existing static patch workflow, and real output includes the repaired copy and patch ZIP. No attachment code or suggested tests were executed and no PR was created. The observed patch adds only `encoding='utf-8'` to a unique original span.
- **Queued tasks:** A queued business job deterministically ends the current model turn with a queue receipt; it does not consume another model round to poll a job that waits for chat completion or claim the file is already finished.

## Test classes and limits

`tests/focus18.test.mjs` covers original routing requests, complete text beyond the preview cap, release bodies, mail inheritance, actual generated XLSX expiry blanks, blocked/cached recognition, ambiguity hints, static patch dispatch, historical-cell preservation, queue settlement and template/key binding. Full regression and the standard real-browser smoke must pass on the final clean commit.

`qa-output/focus18/` retains the first real-browser attempt, targeted recovery attempts, original model sessions and exact run/artifact/hash records. The test driver reads only REQUEST.txt and INPUTS plus the active scope; CHECKLIST, reviews and reference answers are never uploaded or inserted into product prompts. All source bytes are checked separately by the developer verifier.

The developer HTTP model budget started at 64 and was explicitly extended once to a maximum 72 to cover a newly found protected-scenario delivery regression. It was not reset between service restarts. After that cap, a remaining call produced a budget-gate Connection error; this is not reported as an intranet outage. No further live model runs are authorized by this script once exhausted.

**10 has an important evidence boundary:** the last live model run produced an `append_ledger` call but failed after a misplaced development guard blocked it, and the model budget was exhausted. The guard location was corrected and covered by regression. Its real captured tool arguments were then replayed through the production queue/processor with the same original bytes and request, zero model POSTs, producing a verified workbook with five appended records. This backend replay is not a fresh passing model end-to-end test. Independent QA must repeat the complete UI path.

07 has explicit OCR limits; 12 only checks `[]` handling; 16/18/20 stay blocked for missing authentic material/provider conditions. Independent QA, not developer `done` status or input readiness, decides scenario acceptance. The older tax-total defect belongs to the prior batch and is not silently added to this scope.
