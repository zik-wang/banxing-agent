# S15 术语展示与字段核验修复

本批仅处理 S15-TERM-001、S15-VERIFY-002，基线 1946c5b；不更新 main、旧便携包或原离线 HTML。当前验收范围仍为 01–20 除 02、17，21–28 暂停。

## 原因与改动

历史视觉回执只返回字段框架；OCR及文字层包含正文。原运行仅登记两次调用，模型将调用完成写成全部字段一致。导出上一答复时直接固化这份表述。原文中的全称被模型压缩，与OCR错误无关。

`media-verification.mjs` 将实际返回的标签值/表格值登记为字段证据，保存文件哈希、读取器、原值、原始文本偏移及页覆盖。按记录键和字段键对齐，区分缺证据、单侧、冲突、严格匹配；重复键不按顺序强行配对。只有框架或空值不产生有效字段。OCR与文字层是单独的第三路检查，不冒充视觉/OCR独立复核。没有检查不报告“零差异”。

`document-tools.mjs` 本地读取原PDF实际页数，记录转换图片数量、仅发送一张、页码映射是否明确。多页PDF第一张转换图的真实页码未知时保持未知。`intranet-media.mjs` 的OCR覆盖来自有效的原始 page_idx 回执；`workspace.mjs` 保存覆盖。读取完成不代表所有页理解正确。

`source-presentation.mjs` 从当前授权的文字/OCR原文提取术语及逐字跨度。默认提示要求业务含义用中文说明并保留全称/已有缩写，企业与产品专名保留原文。仅对完整、唯一匹配的来源术语修复 and/& 改写和推导出的新简称，不能全局替换连接词；原文已有 &、ERP/HR/CRM等不被统一改写。没有证据的缩写不猜中文全称，并列产品后的括号简称不擅自关联到整个组。

模型输出仍缺中文解释或删失全称时，仅允许一次展示修订，复用已有证据，不重复识别，不升格核验。最终程序检查仍可独立发现偏差、恢复可确定的原文或保留待核，不以修订模型的自述作为正确性证明。

聊天、直接导出、上一答复导出及公共交付边界使用同一检查器。原模型回答保留在 `rawModelAnswer`，结构化记录在 `responseIntegrity`、`mediaReadings`、`mediaVerification`；导出任务也保存对应审计和告警。程序只允许自己的字段统计说明核验范围，自然语言中未绑定字段的核验断言降为待核。日期、网址、邮箱、文件扩展名和Markdown表格结构不得因检查器而丢失或被拆断。

## 验证与复验

专项测试：`node --test --test-concurrency=1 tests/s15-source-integrity.test.mjs`。完整回归：`node --test --test-concurrency=1 tests/*.test.mjs`。本轮实际计数、首次失败、最终通过、真实调用日志、截图、DOCX下载及历史回放见 `qa-output/s15-fixes-20261027/`，不沿用历史测试成绩。

真实测试只将同一公开PDF、原样首次请求和原样Word请求传给产品；QA检查、期望答案和本工单均不进入模型上下文。真实调用、历史模型输出离线回放、机械回读和代码测试分别记载。开发自测不替代独立QA。

## 明确限制

术语提取和自然语言断言定位是保守的启发式，不能证明任意术语/变体完全被发现；中文解释仍可能错误，未建立独立语义gold。自由段落及无法确定标签/记录身份的内容保持未验证。严格文字匹配只证明已登记值相同，不证明事实正确、全部语义或全页完整。并列关系、时区、合同当前状态等其他问题仍需按既有待核记录处理。本批不扩展其余旧缺陷，也不把修复候选直接更新为正式展示结论。
