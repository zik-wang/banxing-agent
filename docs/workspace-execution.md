# 隔离执行工作区与18场景回归

宿主在 `workspaceExecution` 中显式配置 `enabled: true`、`backend: "codex-mxc"` 及 Codex/Python/PowerShell 可执行文件绝对路径。`readOnlyRuntimeRoots` 只配置受信任的已安装运行库目录。本功能仅使用 Codex 的原生Windows沙箱，不调用Codex模型；规划仍使用宿主选择的千问。

每次运行拥有独立 `command-workspace`：原件按SHA复制到只读 `inputs/`，生成代码和数据在可写 `work/`，无凭据的沙箱配置在不可向模型读取的 `control/`。模型不能提供权限profile、宿主可执行文件路径或扩大目录范围。网络关闭；不支持MXC或沙箱启动失败时不回退到宿主直接执行。

`workspace_files/read/write/run/publish` 分别提供目录元数据、分页文本读取、生成文件写入、Python/PowerShell执行和真实成果登记。命令有宿主时间/输出限制，取消和超时终止本次进程树。输入、目录穿越、junction、符号链接和硬链接受到独立检查。发布支持文本、CSV、JSON、DOCX、XLSX、PDF，实际重开文件和结构后才成为下载成果；这不证明业务内容正确。

本地私密录音/转写政策不允许开放通用执行器或读取其内容。“不要运行代码”等原任务禁令会移除通用命令工具；静态补丁等原有专用工具保留。未实现容器级CPU/磁盘配额，也不承诺任意缺失软件可用；离线执行不自动安装联网依赖。

## 固定回归

`benchmarks/scenario-regression/prepare.mjs` 从既有intake和active-scope冻结18项原REQUEST与原件SHA。当前原材料包明确缺少16/18/20的订单、录音、巡检输入，这三项保持阻断。未使用合成原件填补。

`run.mjs` 对baseline/candidate分别运行原任务及“保持实际回复的事实与限制，仅转Markdown、不重新分析”的续接变体，共72个结果槽位。基线8ae6854与候选版使用相同硅基流动Qwen/Qwen3.8-27B、采样参数和每项8次累计入口/10分钟预算；变体共享该项网关预算，失败基线不得导出错误消息冒充成果。原指令不加统一的文件生成要求，不改变任务授权。

网关统一节流与记录实际POST、HTTP、usage、缺失usage和失败，最多160次全套推理请求；预算拒绝与服务商限流分开。接口和文件成功不自动算业务正确；内容依据、未完成范围及条件阻断单列。继续运行已有suite会跳过已完成结果，拒绝覆盖已开始但未结算的任务。

本机执行清单、原件、双版本回执及结果在工作树父目录 `qa-output/workspace-regression-20261104`。密钥只由回环网关读取，不复制到原件、候选工作区或发布包。

冻结基线为 `8ae6854be6d50e262892f80b67fa1f6513dabcc8`，冻结候选版为 `6fae33460675a16aa189491b7efb0930e3d9f23e`。72个槽位均有结算记录，其中包含阻断和未完成项；不是72项通过。真实模型POST共98次，已返回usage合计1,080,606 tokens，13次请求没有usage，费用未知。

服务商有10次HTTP402、code30001、余额不足响应；4条请求中断记录中有一条在节流等待时结束，未实际POST。相同源文件、模型及预算已固定，但执行顺序未随机化，服务商可用性影响了后续任务。本轮不足以证明新版整体优于基线，更不能证明已达到Codex整体能力。原任务技术结束：基线5项、候选4项；对应的9个格式续接全部以零新推理完成实际Markdown保真转换。技术结束仍需源审，独立人工Gold为0。

另设明确要求通用Python的能力探针，未冒充原18场景盲测：真实千问执行两次隔离Python命令，第一次发布路径错误后纠正并发布CSV。独立openpyxl/Decimal复算25行、25个供应商、合计266185556.75，与实际CSV完全一致。此探针6次真实POST、45,636 tokens，与18场景调用分开计数。两部分合计104次POST、1,126,242已知tokens；没有为失败项另行放宽预算或自动充值重跑。

最终代码还收紧了动态导入原件的授权与SHA校验、私密本地政策、控制目录拒绝及配置重写，并保留硅基流动根级错误码诊断。这些后续修改通过104项相关测试；冻结18场景没有在这些后续修改上重新调用模型。真实沙箱测试包含Python/PowerShell、DOCX/XLSX回读、原件与越界读写拒绝、回环网络拒绝、凭据不继承、控制配置拒写、进程树超时终止与输出洪泛停止。

报告生成：`node benchmarks/scenario-regression/report.mjs <suite/manifest.json>`，生成可离线打开的 `逐例回归报告.html` 和 `comparison.json`。页面保留原任务、模型实际答复、错误和工具轨迹，并内嵌原件与实际成果的下载字节和SHA；不把错误答复转换成完成文件。浏览器离线核对18行、筛选及三个真实下载SHA，桌面1440与手机390宽均无横向溢出。开发检查不代表用户验收。

## 充值后恢复与上下文修复

用户补充硅基流动额度后，新一轮完整对照另存 `qa-output/workspace-regression-recharged-20261104`，冻结基线8ae6854、加固候选ed0e7c7，模型和预算不变，旧结果不覆盖。模型接口恢复成功响应，但响应中断与其他失败仍按实际记录。

复查旧执行轨迹发现：旧压缩器只保留最近两条完整工具回复，即使三份短材料合计很小，也会丢掉已读原文，诱导规划模型反复调用read_tool_receipt直至预算用尽。修复为先保留合计48,000字符以内的工具内容，超限才从最旧且已被模型看到的回复压缩；最新两条和未首次暴露给模型的并行回复保留。恢复提示直接定位/data/text，已恢复片段的提示指回原回执及原范围，避免重复嵌套包装。

48,000字符是工具载荷的保留阈值，不是整个上下文的硬token限制；系统提示、用户禁令、模型调用参数和协议配对不会因此删除，过大的新回复仍优先完整呈现。修复不增加模型轮次或请求预算。后续定向模型实测单独记录，不混入已冻结完整对照。

独立评估器还修复了一处Word表格漏读：过去正文存在时未将表格文本合并进字段检查，导致旧候选01的22项目录被误报为缺失。真实DOCX回读已证实22项都在表格中；该任务仍因预算用尽保持partial，不改成业务成功。旧原始回执、文件SHA和旧交付包保留，评估修正说明另存在充值后QA目录。
