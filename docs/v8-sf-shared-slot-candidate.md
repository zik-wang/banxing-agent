# V8 SF 请求级共享槽位候选

这是隔离开发分支的候选改动，未部署或重启 8884，没有新增真实模型请求。此前 T2 的 HTTP429 证据、耗时与金额对照保持不变；不能据此宣布真实财务复核完成或生产全站已受控。

## 行为变化

`v8-tools/siliconflow-queue.mjs` 按实际 URL 主机识别硅基流动，覆盖 `.cn` 和 `.com` API 主机。其他端点直接沿用原 fetch，不占用 SF 槽位；不因 provider 标签或另一把 API key 绕开同一队列。

以下 V8 出站位置接入同一个请求级包装：

- 统一聊天传输，包含通用助理、财务转交和合同审核的模型调用。
- 文档工具的视觉请求。
- 模型连接探测，以及网页 `/api/health` 的模型清单探测。
- 合同审核的模型清单预检。

保留原端点、模型、认证和请求内容。包装完整读取响应后才返回可供原调用方解析的 Response。流式适配器等待实际 SSE 结束，不在 finish_reason 或 `[DONE]` 处提前释放，并保留 Retry-After。断流、响应上限和解析错误不会当作成功。

SF 传输不再自行重试网络错误。429 状态与 Retry-After 随槽位返回值或异常交给公共调度器统一冷却；不在旁路补发请求。非 SF 原有有界重试策略保留。

网络预算在实际即将发送时登记；排队和预算拒绝不计为实际网络尝试。回执新增 `sfQueue.queueWaitMs`、`supplierRequestMs`、`bodyFullyConsumed`，区分排队与供应商响应耗时。旧实验记录不会重算。

## 宿主接入要求

运行候选时须由维护者提供本进程独占的 `V8_SF_WORKER_ID`，例如本工作窗口的 `worker-02`。默认从仓库同级 `local-progress/sf-turn.mjs` 导入现有 `withSiliconflowSlot`；冻结目录位置不同时，可用 `V8_SF_SLOT_MODULE` 指向同一个现有调度模块的绝对文件路径。

模块或 worker 身份不可用时，在发送前明确阻断，不静默直连。候选本身不发现或存储 API 凭证，不修改共享调度服务或其他 worker 状态。上述宿主设置不是用户审核说明，也不能由材料内容或模型输出设置。

一个入口只包一层：不要再给服务器或本模块套 `sf-turn run`。外层 CLI 租约标记及本模块内嵌套会被明确拒绝，避免持锁后等待第二把锁。

排队和实际调用仍受原有任务/请求时间上限。等待期间取消后，即使随后获得槽位也不再发送请求。公共调度客户端目前没有即时取消等待的信号协议，调用返回可能需要等其下一次授予或控制检查；本候选不通过抢锁、清锁或后台旁路来提前返回。

## 实际验证与边界

新增 `tests/v8-siliconflow-queue.test.mjs` 的 16 项离线检查：

- 不同 worker、不同测试 key，经独立 mock FIFO 调度，实际 localhost HTTP 响应不重叠；JSON 未读完不放行。
- SSE 在 finish/DONE 之后仍有尾部 usage 时继续持有槽位；异常断流明确失败。
- 429 正常响应及断开的错误响应都保留统一冷却信号，不自行重试。
- 暂停、排队取消、宿主预算拒绝、缺少身份和不可用模块都不产生供应商请求。
- 外层和嵌套租约明确拒绝；非 SF 不占槽。
- 实际视觉方法、连接探测方法和独立端口上的真实网页健康路由走同一包装。

上述16项测试用合成内容、mock 调度器、mock 流和临时 localhost 服务；未申请生产槽位、未调用付费模型。它们验证候选集成和生命周期。另有下述真实跨进程验证，不能将两层证据混为同一项测试。

选定回归还覆盖传输、金额来源计算与 Word 回读、合同流程及证据规则。初次运行发现的沙箱临时目录重命名权限失败已保留为环境记录；改用独立工作区临时目录后通过。进一步回归发现数字型超时错误 code 的兼容性问题，本候选已修复并重测。

04097bc候选阶段选定回归：**128 项通过，0 失败，0 跳过**，其中新增队列检查为 16 项；不是全项目回归。具名测试文件及计数见 `reports/2026-11-05-sf-shared-slot/results.json`。复现时使用 Node 测试运行器，测试并发为 2，并配置已有的 `V8_PYTHON`、`V8_DOCX_MODULE`；测试临时目录应位于有写入与原子重命名权限的独立目录。

## 后续真实跨进程调度 + mock 上游

新增 `tests/v8-sf-process-integration.test.mjs`：每项启动一个真实测试调度 HTTP 服务和两个真实客户端子进程。客户端调用候选 `createChatApi`，仍以实际 SF URL 进入 `queuedProviderFetch` 的 SF 分支，随后仅在测试传输注入中映射到另一独立 localhost 上游端口；不改 DNS、生产端点或认证。

这层使用原共享 `withSiliconflowSlot` 客户端和 `SiliconflowQueue` 实现，不使用16项单元测试中的 mock FIFO。为使远端可重跑，`tests/fixtures/sf-shared-source/` 保存经 SHA256 核对的原调度源码快照和最小合成配置；不含生产运行态或凭证。首次运行使用当时实际本机共享源码；源码身份以 CRLF 规范为 LF 后的 SHA256 固定，同时保留采集时原始字节哈希，避免 Git 换行转换造成误报。测试启动独立 BOARD_DATA、BOARD_PORT，并现场生成测试凭据，不占用生产槽位。

6项集成分别验证：两个 JSON 客户端、两个 SSE 客户端、429共享冷却、暂停、截止、异常断连。实际记录授予、上游开始、完整正文结束和释放顺序；确认并发上限1。429后另一进程在推进测试时钟前不能发起上游请求；异常断连后真实共享客户端保留不确定租约，等待者不会因租约陈旧被自动放行，测试没有清空租约。

测试差异明确保留：测试 gap 为20ms、轮询为25ms；429返回 Retry-After=120秒，使用独立队列时钟推进120100ms验证冷却；陈旧状态使用测试时钟推进100000ms。生产默认60秒间隔未修改。暂停和截止写入独立测试控制文件，在途合成响应自然结束。

可重跑命令：`node --test --test-concurrency=1 tests/v8-sf-process-integration.test.mjs`。可选 `V8_SF_PROCESS_EVIDENCE` 指向现有独立输出目录以保留顺序、回执和测试数据；该目录会包含现场生成的测试凭据，不能整体提交。可选 `V8_SF_TEST_SHARED_ROOT` 指向同版共享源码，哈希不符时明确失败。

另提供显式启用的离线回归预加载器：设 `V8_TEST_LOOPBACK_ONLY=1`，用 `node --import ./tests/helpers/loopback-only.mjs --test ...`，阻断测试进程内非 loopback 的 fetch/HTTP(S) 请求。它不被生产代码导入。跨进程辅助客户端另有固定 SF 逻辑地址和 loopback 传输限制。

此次最终选定回归 **134项通过，0失败，0跳过**，包含原128项与新增6项跨进程验证；不累加多次重跑计数。首次使用本机同版共享源码的6项检查也单独保存。脱敏摘要见 `reports/2026-11-05-sf-crossprocess/results.json`，其中分别保存真实授予次数、上游请求次数、完整正文结束次数、释放次数及排队/请求耗时；测试时间加速不可作为生产性能成绩。
