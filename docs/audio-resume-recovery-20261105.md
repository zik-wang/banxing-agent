# Audio transcription recovery hotfix

Three separate failures were observed in a local-only audio conversation:

1. The historical cloud-mode registry removed `transcribe_audio` even when ASR was local. The host inspected and split the recording, then failed with `UNKNOWN_TOOL`. The local exception was already present in the newer runtime; the old failed turn remains an accurate historical record.
2. A new resume imported a generated WAV segment using `path.extname(displayName)`. The display label ended with a colon-containing time range rather than a real extension. Windows rejected the target path with `ENOENT` before transcription started.
3. During real-page recovery, the browser's empty manual attachment picker set `useConversationFiles=false`. Intake converted this into an exclusion of every original file, even though resume explicitly uses the original task snapshot. The host now applies that temporary picker exclusion only to a new/revised task. Removed files, permission revocation, private-cloud exclusions and continuity scope checks are preserved.

The fix derives the internal asset path from a validated immutable asset ID and the parser's format. It preserves the display name, source relation, original bytes, resource authorization and task identity. Resume, initial workspace import and subsequent resource selection use the same helper. Invalid IDs fail closed. The local host route checks its required registered tools before splitting and returns an actionable configuration failure if one is missing; it never falls back to a cloud planner for private transcription.

Validation performed: 20 focused tests passed, zero skipped, covering the actual continuity checkpoint/import path, same-task resume, cross-task denial, source-bound drafts, explicit synthetic ASR receipts, typed delivery and missing-tool failure. A separate 29-test batch passed for real host resume profiles, chat scheduling and network/history permission boundaries. Nine audio tests and two resume tests also passed against the separate minimal production overlays. Synthetic ASR tests do not establish transcription accuracy. Sandboxed Windows temp-file rename failures were separately identified; the same tests passed in the normal user environment without ACL changes.

Deployment uses a new runtime copied from the running release, with only the audio path/preflight/registration changes applied. Existing UI files are retained byte-for-byte. Other pending draft candidates are not included in that production overlay. Previous runtime, historical failures and original files remain available. The live recovery and download receipts are kept locally, outside Git; recording contents and model weights are not committed.
