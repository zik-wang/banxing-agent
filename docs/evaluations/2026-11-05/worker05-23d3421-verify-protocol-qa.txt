2. 一份输入的独立可复现证据

合成文本由复现脚本固定，包含中文、双引号和换行；无公司材料或真实合同。
  原文 UTF8：50 字节
  SHA256 = 07f30ef0a0a0c9526834bc96dd4b150e444ae2a5ca742803a54bf2f462e28aa9
  JSON 字符串 UTF8：55 字节
  SHA256 = 03091cceb9d8a3600256a7e74b2ed837a2d5eea3ed9a8dcc94a5c6a27e78af2b

Node crypto 与独立 Python hashlib/json 脚本分别计算，以上两个摘要及字节长度逐项一致。计算器返回的 sourceSha256 等于第二种摘要；回执ID按原构造顺序重算一致；引文区间都匹配。用户消息 JSON 往返后的 source 与原字符串完全相同。
差异来自 JSON 字符串的外层引号、内部引号转义及换行转义，不是内容自动改写或哈希碰撞。本例证明的是同一内容、不同字节域，不直接证明历史原文未变。

在同一份合成输入上构造程序夹具，实际调用固定提交的纯校验函数：
  A. decision=verified，输出原文摘要：passed=true，issues=[]。
  B. 只改为输出计算器所用的 JSON 字符串摘要：passed=false，issues=[SOURCE_HASH_MISMATCH]。
  C. 保留原文摘要，只改 decision=rejected：passed=false，issues=[NOT_VERIFIED]。
这些均是明确标识的离线程序夹具，不是模型回答。没有用人工构造 verified 的输出代替真实业务通过。

原公开 results.json 记录的是 modelDecision=rejected、issues=[NOT_VERIFIED]，未列 SOURCE_HASH_MISMATCH。结合上述代码，这与“输出原文摘要正确，但模型对嵌套回执来源标识有疑问而主动拒绝”相容；不能把该历史结果写成宿主摘要判等程序报错。没有审阅本机模型原始解释，无法独立证明模型实际拒绝时的全部依据。
