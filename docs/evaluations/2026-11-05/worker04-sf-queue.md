# worker-04：SF 请求级共享槽位接入

后续硅基流动请求使用本机统一 `withSiliconflowSlot`，一个入口只包一层。当前保守全局单槽，不按API Key另分并发；非SF端点直接使用原传输，不占槽位。这里不宣称平台所有模型的实际配额相同。

## 行为与接线

`qa-support/siliconflow-slot-fetch.mjs` 提供宿主注入的请求包装，完整读取JSON/SSE后才将状态和Retry-After交还共享调度器。流式适配器在此模式下同时等HTTP EOF，不能仅收到DONE就释放。非排队模式的原流式完成行为保留。

本机私有preload实际导入现有调度模块，安装全局fetch包装和SF HTTPS直连拒绝，并由演示服务环境传递给模型子进程。模型客户端的显式流式路径也使用该宿主包装。实验网关要求preload，未安装就拒绝启动；已安装时识别现有包装，防止嵌套申请。

实际启用范围是worker-04独立演示服务的模型请求、SF健康检查、继承环境的模型子进程及后续实验网关。旧直连演示入口已改为拒绝未接线启动；旧网关已退出。归档冻结快照不改写，后续若重用只能经受控入口启动，不能直接恢复旧直连脚本。其他窗口、原站点与其他provider未改。

宿主接线示意（本机路径、worker绑定、认证和运行态不上传）：

```js
installSiliconflowSlotTransport({
  withSlot: (fn, options) => withSiliconflowSlot(workerId, fn, options),
  onRecord: saveMetadataOnly
});
```

宿主preload随Node子进程继承；不要再用 `sf-turn run` 包住同一个已按请求接入的服务或任务。常驻服务器本身不持有槽位。

## 失败与计时

429完整消费后，把原Retry-After交给现有共享调度器的全局冷却与指数退避；包装不自动重试，也不另开旁路。断流/超时无法确认完整消费时返回uncertain，保留租约并拒绝本进程追加SF派发，须实际核实原调用结束后再处理租约，不能盲目清锁。

队列不可用或暂停时不联系供应商；等候中取消的请求即使后来获槽，也不会派发。实际超时/取消仍保留原有宿主时限，不擅自扩充预算；端到端客户端时限可能在排队中用尽，此时不能记成一次供应商请求。新共享排队条件和原对照不同，旧成绩不改写。

每条请求有独立的观察ID，单列 `queueWaitMs`、`providerElapsedMs`、HTTP状态、消费完整性和字节数。日志不包含头、API Key、正文、推理或工具参数。旧的外层总耗时仍是端到端计时，不能拿它冒充供应商耗时。实验网关只在真正开始供应商请求时记 `networkRequestAttempted`。

## 实际核查

本地真实接线检查证明父进程和继承环境的子进程都已安装宿主，直接SF HTTPS被拒绝，未接线网关在读取凭证前拒绝启动。这些检查没有发SF请求，也没有为合成测试占用真实槽位。

旧实验网关均已退出；旧演示进程停止前核实无运行任务、无已建立外部连接，没有强杀在途SF请求。受控演示服务恢复后核实宿主安装、原端点和 `Qwen/Qwen3.8-27B` 不变、无运行任务或新派发，再实际执行 `drained worker-04`。共享服务回执确认本窗口已收尾，`awaiting_drain_workers`为空；不是用收到政策消息冒充确认。已按原命令上报 `SF_QUEUE_READY` 和本机证据路径。

41项关联离线检查通过，包含JSON/SSE完整消费、DONE后保持到EOF、429/Retry-After、断流不追加重试、取消、非SF不占槽、暂停拒绝、重复包装及实际聊天流式路径。所有上游使用注入的合成响应或本地HTTP，没有用模拟429冒充真实平台限流，没有重复104项回归。本次接线不产生新的模型成绩，03原停滞及缺材料项继续保持原记录，业务验收由用户执行。
