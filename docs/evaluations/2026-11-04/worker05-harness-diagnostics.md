# Harness 定向诊断与候选边界

新增两个可独立审查的候选模块：来源提案必须匹配宿主持有的事实账本，缺依据的合同方、时区、续约不能被模型补齐；耗时操作可放入独立子进程，由保持响应的监督进程截止。**两项尚未接入正式网站，不构成线上修复完成或业务验收。**

## 本次代码

- `v8-tools/expiry-proposal-guard.mjs`：校验事实 ID、来源类别、字段角色、日期精度和多值关系；拒绝未知、重复、遗漏及未经验证的附加断言。通过时返回由宿主账本重新投影的 `trustedProposal`，不会将模型对象直接作为可信结果。V2 显式区分应用名称与协议名称，V1 必须显式指定。
- `qa-support/deadline-supervisor.mjs`：监督宿主自己启动的直接子进程；截止、取消或输出超限后停止该进程，晚到退出不算成功。输出有界；未确认回收时返回 `termination_failed`。这不是完整进程树沙箱，也不是新的模型工具权限。
- 新增合成测试及一个无网络子进程夹具，不包含业务原件或模型原始请求。

来源守卫只保护指定结构化接口。账本来自宿主解析器，**不证明来源解析召回率、法律事实或任意自由文稿正确性**。采用时应只渲染通过校验的账本投影；模型说明需要单独标注，不能用文件保存回读替代语义检查。

监督器要求父进程保持响应，宿主休眠会暂停父子进程；只终止直接子进程，不处理其后代。正式接入前仍需确定进程树所有权、唤醒后过期处理、临时文件收尾和晚到回包拒绝策略。

## 实际验证

执行环境：Windows，Node.js 24.22.1。本次6文件独立候选包无需模型、业务材料或额外依赖，运行：

```powershell
node --test tests/v8-expiry-proposal-guard.test.mjs tests/v8-deadline-supervisor.test.mjs
```

结果：**独立候选包19项全部通过，无跳过**。另外在当时本地完整工作树上，连同既有 `tests/v8-expiry-facts.test.mjs` 做了关联验证：首次22通过、4因环境变量未配置而跳过；补充环境后在沙箱临时目录出现23通过、3失败，包含原子改名EPERM；改用工作区受控临时目录后，**26通过、0失败、0跳过**，包含PDF、五格式、断点恢复和Word转换。初始失败记录保留，没有将环境复核通过说成生产故障已修复。

本次从远端工作分支当时的 `c9f25ab` 单独构建只含这6个文件的提交，避免上传本地领先远端的36个其他提交。独立19项在仅有这6个文件的目录复验通过；本地完整工作树的关联检查基线为 `3767cf9`。二者不能冒称同一完整版本已做全站验证。

- 新监督器测试中，600ms 截止在约611ms回收被同步阻塞的子进程，未接受其晚到成功输出；取消前不启动、运行中取消、输出截断、非零退出和启动失败均有定向检查。
- 来源守卫测试覆盖供应商角色互填、产品/协议名混淆、无源时区、日期精度、多值配对、事实身份、附加断言及可信投影不反向修改账本。
- 本轮没有运行全站回归、部署测试或用户验收。

## 已完成的真实请求诊断

此前获准的公开材料仅在本机用于诊断，原件、完整提示词、模型原始输出、登录状态及认证配置不随本提交上传。

2026-11-04新增3次 `Qwen/Qwen3.8-27B` 请求，均HTTP200，已知usage合计25,653 tokens；保持原温度0.1、top_p 0.95、max_tokens 8192、关闭思考、非流式及300秒请求时限，没有换模型。HTTP成功只说明单次请求返回，不等于完整业务任务通过。

1. **原失败请求重放**：请求JSON与历史失败请求一致，约3.33秒返回下一步工具提案。历史约934.7秒超限未复现，根因仍未知。本次直连原获准上游，旁路历史本机网关和节流队列；不能称整个旧运行栈等价，也不能据此比较框架速度。
2. **来源字段诊断**：约87.29秒返回18项提案。合同供应商和时区保持空值，两组多值关系未配对，仅年精度保留；仍观察到17处产品名进入协议名、1处协议品牌被推断为应用供应商。首版诊断接口对日期精度及配对枚举定义不够清楚，其相应拒绝不能全部计作事实错误。实际提案未通过候选守卫。
3. **明确接口后的诊断**：约3.61秒返回工具调用而非所需JSON，未执行该调用，因此没有新的语义通过结果。没有为取得预期答案而静默禁用工具或扩大调用循环。

已将原系统提示、工具目录、宿主预读取、追加诊断指令及账本模式的差异分别记录于本机。基线代码、提示和工具使用路径并非完全相同，不能把整体结果归因于某一个框架内核，也不能将有限协议适配称为Codex官方后台替换或全场景支持。

本机还完成一个零模型调用的机制实验：200ms协作式超时在900ms同步阻塞后才于约923ms触发；独立监督约235ms停止同样被阻塞的工作进程。这证明机制风险，**不证明它就是历史934.7秒事件的原因**。三次真实请求都在300秒前返回，真实300秒超时触发路径仍未覆盖。
