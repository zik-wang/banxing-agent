# Personal Agent 场景设计方案

> **20 个可通过工具执行、可交付结果、可核查完成状态的个人代理场景。**
>
> 从一次性文件处理，到跨天持续跟进：让 Agent 不只是回答问题，而是完成明确授权的任务。

**适用方向：** 网页版 Personal Agent、用户上传文件、服务端沙盒及授权数据源接入。
**文档用途：** 场景筛选、产品需求讨论、MVP 规划与验收标准设计。

## 一、设计原则与执行前提

### 1. 每个场景都必须有可验证的交付物

场景统一按照 **用户指令 → 工具调用链 → 结果交付 → 边界与验收** 展开。完成状态应对应实际产生的文件、日历事件、任务记录、发送记录、PR 或通知记录，不能只依赖模型的一句“已经处理好了”。

### 2. 区分一次交办与持续委托

| 任务类型 | 执行特点 | 完成或结束条件 |
| :--- | :--- | :--- |
| 即时任务 | 用户交办后，围绕确定的输入连续执行 | 交付结果并通过校验 |
| 批处理任务 | 对一批文件、网页或媒体逐项处理 | 输出成功项、失败项和汇总结果 |
| 多轮任务 | 需要等待他人回复或补充信息 | 达成目标，或按约定终止 |
| 定时任务 | 在用户指定时间重复执行 | 每次执行分别记录结果；委托持续至停用或到期 |
| 持续任务 | 跨天监控外部状态，满足条件才行动 | 达到目标、达到次数上限、到期或用户取消 |

### 3. 授权、数据与运行条件必须明确

数据仅来自用户上传或授权的数据源，不默认访问用户电脑、对方日历或第三方账户。发信、发送邀请、修改共享资料等动作必须具有明确授权；可以在用户批准的模板、次数和范围内执行，不擅自扩大权限。

付款、永久删除、自动续约、合并主分支及生产环境变更，不纳入默认自动执行范围。持续任务需要产品实际具备调度、持久化状态和通知能力；等待对方回复或接口暂不可用时，应展示真实状态。

> **能力说明：** 下文的“所需工具”是产品设计所需能力，不代表这些接口已经接入，也不代表场景中的任务已经执行。工具接入范围、权限和可用性需要在实现阶段核验。

<a id="communication"></a>
## 三、时间管理与沟通

把零散的信息变成安排，把一次交办推进到有记录、可核查的结果。

<a id="scenario-01"></a>
### 01｜每日重点事项简报

**任务类型：** 定时任务

**用户指令**

> 每天早上八点，结合我的日历、邮件和待办，告诉我今天最重要的三件事，以及有哪些时间冲突。

**工具调用链**

定时触发 → 读取日历 → 检索未处理邮件 → 读取待办及截止日期 → 按用户规则排序 → 发送简报

**所需工具：** 任务调度、日历读取、邮件检索、待办读取、通知发送。

**交付与完成标准：** 交付当天安排，包含会议、优先事项、即将到期的任务与时间冲突；每项内容可以点回原始邮件、日历事件或待办。

**边界与验收：** 没有明确截止日期的事项，不自行编造日期；优先级依据用户设定与已有事实；不擅自移动已有会议。

<a id="scenario-02"></a>
### 02｜自动协调并预约会议

**任务类型：** 多轮任务

**用户指令**

> 下周帮我和张总约半小时，优先下午，避开我已有的安排。

**工具调用链**

查询联系人 → 查询本人空闲时间 → 查询对方共享空闲时间或发送候选时段 → 检查回复 → 创建事件 → 发送邀请

**所需工具：** 联系人查询、日历空闲查询、邮件收发、日历创建、任务状态存储。

**交付与完成标准：** 创建包含正确参会人、时间、时区及会议方式的日历事件，并返回事件链接与邀请状态。

**边界与验收：** 不能假设能读取对方日历；没有共享权限时通过候选时间协调。对方尚未回复时标记“等待确认”，不能宣称会议已经约好。

<a id="scenario-03"></a>
### 03｜会前背景资料准备

**任务类型：** 即时任务

**用户指令**

> 下午我要见这个客户，帮我整理上次聊了什么、哪些事情还没解决，以及今天应该确认的问题。

**工具调用链**

读取会议 → 查找关联联系人 → 检索往来邮件、历史纪要和项目文件 → 提取未决事项 → 生成并保存简报

**所需工具：** 日历读取、联系人查询、邮件检索、文件检索、文档生成。

**交付与完成标准：** 交付一份会前简报，列出上次结论、未完成承诺、待确认问题与相关材料链接。

**边界与验收：** 事实必须能追溯到原文；推测和建议单独标注，不写成客户已经确认的意见。

<a id="scenario-04"></a>
### 04｜会议录音转纪要与待办

**任务类型：** 即时任务

**用户指令**

> 这是刚才的会议录音。整理纪要，把明确交给我的事情放进待办，有明确日期的加上提醒。

**工具调用链**

读取音频 → 语音转写 → 提取结论、负责人和期限 → 生成纪要 → 创建待办及提醒 → 归档录音

**所需工具：** 文件读取、语音识别（ASR）、文档生成、待办创建、提醒设置、文件归档。

**交付与完成标准：** 交付纪要文件和实际创建的待办记录；每项任务关联录音时间点，有明确期限的事项设置提醒。

**边界与验收：** 负责人或期限没有说清楚时标注“待确认”，不自行补全；不能把“生成了一段总结”视为已经创建待办。

<a id="scenario-05"></a>
### 05｜未回复邮件持续跟进

**任务类型：** 持续任务

**用户指令**

> 帮我盯着这封报价邮件。三个工作日没回复，就按我确认的模板催一次；对方回复后停止催办。

**工具调用链**

记录邮件线程 → 按约定日历计算工作日 → 定时查询新回复 → 检查催办条件 → 按授权发送邮件 → 更新状态

**所需工具：** 邮件线程读取、工作日计算、任务调度、邮件发送、持久化状态存储。

**交付与完成标准：** 区分“等待回复”“已催办”“收到回复”“到期结束”，保存发送记录，并避免重复催办。

**边界与验收：** 明确催办次数、模板与结束条件；收到回复后停止。Agent 可以完成跟进流程，但不能保证对方一定回复。

<a id="documents"></a>
## 四、文件与文档处理

以真实文件为输入，以整理后的文件、表格和变更记录为交付物。

<a id="scenario-06"></a>
### 06｜查找最终文件与确认依据

**任务类型：** 即时任务

**用户指令**

> 帮我找到这个项目最终确认的报价单，以及客户同意这个报价的邮件，整理到一个资料包里。

**工具调用链**

检索文件与邮件 → 比较版本和时间 → 核对邮件引用附件 → 复制材料到指定目录 → 生成索引

**所需工具：** 文件检索、邮件检索、附件读取、版本比较、文件复制、索引生成。

**交付与完成标准：** 交付“报价单＋确认邮件＋索引说明”的资料包，说明认定最终版本的依据。

**边界与验收：** 不能仅凭文件名含有“最终版”就认定最终版本；证据不足时保留候选文件，明确缺少什么确认依据。

<a id="scenario-07"></a>
### 07｜混乱文件分类与统一命名

**任务类型：** 即时任务

**用户指令**

> 把我上传的这些文件按项目和月份整理，统一命名，重复文件单独放一边。

**工具调用链**

读取目录 → 提取内容和元数据 → 分类 → 计算文件哈希识别完全重复项 → 复制或重命名 → 生成清单

**所需工具：** 目录读取、文档解析、哈希计算、文件复制与重命名、清单生成。

**交付与完成标准：** 交付整理后的文件夹，以及“原路径—新路径”对应表；无法确定归属的文件放入待确认目录。

**边界与验收：** 完全重复与内容相似分别处理；疑似重复只标记，不直接删除。保留原件或可恢复的映射，避免整理后无法回溯。

<a id="scenario-08"></a>
### 08｜合同或方案版本比较

**任务类型：** 即时任务

**用户指令**

> 比较这两个版本，把金额、日期、责任和交付要求的变化全部列出来，并生成修改对照表。

**工具调用链**

解析两份文件 → 按条款或段落对齐 → 比较文本差异 → 提取关键字段变化 → 生成对照表 → 保存结果

**所需工具：** 文档解析、段落对齐、文本差异比较、结构化字段提取、Word 或 Excel 生成。

**交付与完成标准：** 交付包含“原文—修改后—位置—变化说明”的对照表，覆盖新增、删除及修改内容，原文件保持不变。

**边界与验收：** 工具负责准确呈现变化；涉及法律判断时，应区分自动分析与专业审查，不把自动生成的意见冒充已经完成的专业审查。

<a id="scenario-09"></a>
### 09｜票据整理与报销包生成

**任务类型：** 即时任务

**用户指令**

> 把这些发票按我的报销模板填进去，检查重复和金额，附件顺序要和表格一致。

**工具调用链**

解析票据 → 提取日期、金额和发票号码 → 检查重复 → 计算合计 → 填写模板 → 附件编号 → 打包

**所需工具：** PDF 解析、票据图像识别、字段校验、数值计算、Excel 编辑、文件重命名与打包。

**交付与完成标准：** 交付报销表、按表格行号排列的附件及异常清单；表格金额与附件可以逐项核对。

**边界与验收：** 无法识别的字段、缺失附件与疑似重复项明确列出，不为填满表格而猜测；生成报销材料不等于已经提交审批。

<a id="scenario-10"></a>
### 10｜按规则追加业务台账

**任务类型：** 即时任务

**用户指令**

> 把这批采购审查文件追加到台账，历史记录不要动，新增加的数据用蓝色，有终审的按终审摘录。

**工具调用链**

读取现有台账 → 解析新文件 → 应用摘录规则 → 检查重复 → 追加数据并设置格式 → 校验前后差异 → 保存新版本

**所需工具：** 文件读取、文档解析、规则执行、Excel 读写、重复检测、变更校验。

**交付与完成标准：** 交付更新后的台账与本次变更清单，核验历史区域未被修改，并保留新记录对应的来源文件。

**边界与验收：** 仅在指定范围追加；重复记录按既定规则处理，不擅自覆盖历史数据。适用于采购审查、合同管理及咨询意见整理。

<a id="knowledge"></a>
## 五、持续跟踪与个人知识

持续关注用户指定的信息，把分散的记录沉淀为可复用的知识与提醒。

<a id="scenario-11"></a>
### 11｜有依据的个人周报

**任务类型：** 定时任务

**用户指令**

> 每周五整理我本周完成了什么、还卡着什么，以及下周要处理什么。

**工具调用链**

读取任务变更 → 检索相关邮件 → 读取项目文档或代码提交 → 汇总完成证据 → 生成周报 → 保存

**所需工具：** 任务查询、邮件检索、文件检索、代码仓库读取、文档生成、任务调度。

**交付与完成标准：** 交付完成事项、阻塞事项和下周待办，并关联任务、文件或提交记录。

**边界与验收：** 日历中出现一场会议不等于对应工作已经完成；区分已完成、正在推进和仅被讨论过的事项。

<a id="scenario-12"></a>
### 12｜开源项目相关更新监控

**任务类型：** 持续任务

**用户指令**

> 盯着我关注的推理框架，只看正式版。涉及我使用的模型支持、显存占用或者并发能力变化时再通知我。

**工具调用链**

读取关注项目与个人配置 → 定时查询正式发布 → 读取说明及关联变更 → 匹配关注条件 → 比较上次结果 → 通知并记录

**所需工具：** 代码仓库发布查询、网页读取、配置存储、任务调度、通知发送、去重记录。

**交付与完成标准：** 每次通知说明“哪个版本、发生了什么、为什么与你相关”，附原始来源；没有相关变化就不通知。

**边界与验收：** 明确正式版与预发布版的筛选规则；同一版本不反复通知；发布说明中的性能描述不能自动视为在用户设备上的实测结果。

<a id="scenario-13"></a>
### 13｜技术选型与可核查比较

**任务类型：** 即时任务

**用户指令**

> 找几个适合私有化部署的语音 Agent 框架，比较流式、打断、本地模型接入和部署复杂度。

**工具调用链**

搜索候选方案 → 读取官方文档和仓库 → 提取功能及许可证信息 → 条件允许时运行最小示例 → 生成比较表与报告 → 保存

**所需工具：** 网页搜索、网页读取、仓库读取、隔离沙盒执行、表格与文档生成。

**交付与完成标准：** 交付带来源、查询日期及版本信息的比较表，明确区分“文档宣称支持”“实际测试通过”“尚未验证”。

**边界与验收：** 运行示例需要可用环境、依赖和授权；缺少测试条件时标明限制，不能把搜到的项目介绍写成实测结论。

<a id="scenario-14"></a>
### 14｜收藏内容沉淀为个人知识库

**任务类型：** 批处理任务

**用户指令**

> 把我这周收藏的文章整理进知识库，按主题分类，重复内容合并，保留出处。

**工具调用链**

读取收藏列表 → 获取可访问网页 → 提取正文 → 去重与分类 → 生成笔记 → 写入知识库及检索索引 → 验证检索

**所需工具：** 收藏读取、网页获取、正文提取、去重、笔记写入、索引更新、检索测试。

**交付与完成标准：** 交付已经入库、能够搜索到的知识条目，保留来源链接和整理时间，而不是只生成一份待导入文本。

**边界与验收：** 仅获取有权访问的内容；不同观点分别保留，不能为合并条目而抹平分歧；网页无法访问时记录失败项。

<a id="scenario-15"></a>
### 15｜订阅、域名与合同到期管理

**任务类型：** 持续任务

**用户指令**

> 整理我的软件订阅、域名和服务合同到期时间，提前三十天和七天提醒，不要替我付款。

**工具调用链**

检索授权邮箱、账单和合同 → 提取到期日与续费条款 → 写入台账 → 创建提醒 → 检查后续续费确认 → 更新状态

**所需工具：** 邮件检索、文件解析、表格读写、提醒创建、任务调度、状态存储。

**交付与完成标准：** 交付到期台账与已建立的提醒，记录日期来源、提醒时间及续费确认状态。

**边界与验收：** 付款日期不一定等于到期日期，无法确认的单独列出；到期管理不包含自动付款、续约或取消订阅。

<a id="life-and-technical"></a>
## 六、生活安排与技术事务

把跨系统的零散操作串成完整任务，同时保留清晰的权限和风险边界。

<a id="scenario-16"></a>
### 16｜出差订单整合与行程安排

**任务类型：** 即时任务

**用户指令**

> 把这次出差的机票、酒店和会议整理成行程，检查有没有冲突，加进我的日历。

**工具调用链**

读取订单邮件或凭证 → 提取航班、住宿和会议时间 → 统一时区 → 查询地点与交通耗时 → 检查冲突 → 创建事件 → 生成行程单

**所需工具：** 邮件与附件读取、订单解析、地图或路线查询、时区转换、日历创建、文档生成。

**交付与完成标准：** 交付日历事件及行程单，集中展示订单信息，标出可能赶不上的安排和需要用户确认的冲突。

**边界与验收：** 交通耗时标注为估计；不擅自改签、取消预订或修改会议。订单信息仅写入授权的日历或文件位置。

<a id="scenario-17"></a>
### 17｜物流跟踪与异常通知

**任务类型：** 持续任务

**用户指令**

> 帮我盯着这几个快递，签收时告诉我；超过承诺送达时间还没到，也通知我。

**工具调用链**

读取订单或运单 → 调用已接入的物流接口 → 定时检查状态 → 比较上次结果及承诺时限 → 通知 → 签收后停止

**所需工具：** 订单读取、物流查询、任务调度、状态存储、通知发送。

**交付与完成标准：** 保留最新物流状态、查询时间和通知记录，只对用户指定的变化发送通知。

**边界与验收：** 没有明确承诺送达时间时，不自行认定逾期；查询失败与物流停滞分别处理。查询能力以实际接入的物流服务为准。

<a id="scenario-18"></a>
### 18｜长音视频整理与主题片段导出

**任务类型：** 批处理任务

**用户指令**

> 把这两个小时的录音和视频整理成时间线，把讨论报价、技术方案和后续计划的片段分别导出来。

**工具调用链**

读取媒体 → 分段转写 → 必要时抽帧与视觉分析 → 合并全局时间戳 → 建立主题索引 → 裁剪片段 → 生成目录

**所需工具：** 媒体读取、语音识别、视频抽帧、视觉分析、检索索引、媒体裁剪、文件生成。

**交付与完成标准：** 交付时间线、可搜索转写稿及实际裁剪出的片段；每段标明原文件和起止时间。

**边界与验收：** 分段处理后要校正全局时间戳，避免导出错位；不能只给出“重点大约在第十分钟”而不导出用户要求的文件。

<a id="scenario-19"></a>
### 19｜限定范围的代码修复与 PR 交付

**任务类型：** 即时任务

**用户指令**

> 这个脚本读取中文 CSV 会报编码错误。帮我修复，补上测试，在单独分支提交 PR，不要合并主分支。

**工具调用链**

读取仓库与日志 → 在隔离沙盒复现 → 修改代码 → 添加测试 → 运行测试 → 检查差异 → 按授权创建分支和 PR

**所需工具：** 仓库读取、隔离代码执行、文件编辑、测试运行、分支创建、Pull Request 创建。

**交付与完成标准：** 交付可检查的代码差异、测试结果及 PR 链接；无法复现或测试未通过时如实标记。

**边界与验收：** 仅修改指定问题，不顺手重构整个项目；不合并主分支、不部署生产环境；不把未通过验证的修改宣称为修复成功。

<a id="scenario-20"></a>
### 20｜服务器与模型服务定期巡检

**任务类型：** 定时任务

**用户指令**

> 每天检查我的推理服务、GPU 和磁盘，出现服务不可用或者磁盘快满时通知我，不要自动重启。

**工具调用链**

定时触发 → 通过受限监控接口或只读 SSH 获取指标 → 检查健康接口 → 读取必要日志 → 按阈值判断 → 异常复查 → 发送报告

**所需工具：** 任务调度、受限 SSH 或监控接口、HTTP 健康检查、日志读取、阈值检测、通知发送。

**交付与完成标准：** 交付带时间戳的检查记录；异常通知包含实际指标和相关日志，恢复后关闭告警，避免重复刷屏。

**边界与验收：** 区分“无法连接服务器”与“服务已经故障”；阈值由用户确认；不自动重启、不清理磁盘、不修改生产配置。

<a id="implementation"></a>
## 七、首版落地建议

### 1. 第一阶段：先做输入和输出明确的任务

**建议优先落地 04、07、08、09、10。** 这组任务可以围绕“上传文件 → 服务端沙盒处理 → 校验 → 交付结果”建立共同流程，减少第一版对外部个人账户的依赖。

| 优先场景 | 首版交付范围 | 重点验收项 |
| :--- | :--- | :--- |
| 04 会议录音转纪要与待办 | 纪要文件；接入自有待办存储后创建任务 | 结论有依据；任务与时间点对应；不编造负责人或期限 |
| 07 文件分类与统一命名 | 整理后的目录、文件清单、路径映射 | 不丢文件；重复处理可追溯；原件可恢复 |
| 08 版本比较 | 条款或段落级差异对照表 | 新增、删除与修改完整；原文位置可核查 |
| 09 报销包生成 | 按模板填写的报销表与顺序附件 | 金额准确；附件对应；异常不被隐去 |
| 10 业务台账追加 | 更新后的台账与变更清单 | 历史区域不变；新增范围正确；来源可追溯 |

其中，场景 04 的“生成纪要”和“创建待办”应分别记录结果。未接入待办工具时，可以交付待办清单，但不能声称已经写入任务系统。

### 2. 第二阶段：增加跨天持续执行能力

**建议进一步落地 01、05、12、15、17。** 这组任务的价值在于记住委托、持续检查、等待外部变化、采取授权动作，并在结束条件满足后停止。

| 场景 | 必须持久化的关键信息 | 结束或暂停条件 |
| :--- | :--- | :--- |
| 01 每日重点事项简报 | 发送时间、时区、数据范围、已发送日期 | 用户停用或委托到期 |
| 05 邮件跟进 | 邮件线程、催办模板、等待期限、已催次数 | 收到回复、达到次数上限或到期 |
| 12 项目更新监控 | 关注项目、版本规则、个人配置、已通知版本 | 用户停用或移除关注项目 |
| 15 到期管理 | 到期日期、来源、提醒节点、续费状态 | 原提醒完成；确认续费后按授权更新周期 |
| 17 物流跟踪 | 运单、承诺时限、上次状态、已通知变化 | 签收、用户取消或达到查询期限 |

持续执行不应等同于反复发送消息。应按用户指定的变化条件通知，并设置去重、失败重试和终止规则。

### 3. 复用工具能力，不必为每个场景单独造一个 Agent

可以让同一个 Agent 使用可复用的工具，再为不同场景配置输入规则、执行流程、权限边界和验收要求。

| 能力层 | 主要职责 | 对应场景示例 |
| :--- | :--- | :--- |
| 数据读取 | 读取上传文件、邮件、日历、任务、网页和仓库 | 会前简报、最终文件查找、技术选型 |
| 处理与执行 | 文档解析、语音转写、表格处理、媒体裁剪、隔离代码执行 | 报销包、台账、音视频整理、代码修复 |
| 外部写入 | 创建事件、任务、邮件、笔记和 PR | 会议预约、待办创建、邮件催办 |
| 调度与状态 | 定时触发、等待、重试、去重、取消和状态持久化 | 更新监控、到期提醒、物流跟踪 |
| 验证与审计 | 校验输出、记录来源与变更、核对实际执行结果 | 全部场景 |

### 4. 每项任务至少保存六类信息

| 信息 | 应记录的内容 |
| :--- | :--- |
| 目标 | 用户希望完成什么，交付物是什么 |
| 数据范围 | 可访问的账户、目录、文件、线程或项目 |
| 授权边界 | 允许的写入、发送、修改范围，以及禁止动作 |
| 当前状态 | 待执行、执行中、等待回复、待授权、部分完成、已完成、失败或已取消 |
| 下次触发条件 | 指定时间、外部状态变化、回复到达或重试条件 |
| 完成证据 | 文件路径、事件 ID、任务 ID、发送记录、PR 链接、校验报告或通知记录 |

“等待回复”不是“已完成”；“部分文件成功”不是“全部成功”；“生成了内容”也不等于“已写入外部系统”。外部操作成功后，应保存返回标识；必要时回读核验，重试时避免重复创建或发送。

### 5. 用同一套问题验收所有场景

验收时同时检查：输入来源能否追溯，结果是否真实产生，输出内容是否通过校验，实际动作是否在授权范围内，以及失败、等待和部分完成是否如实呈现。

对于持续任务，再增加两项检查：同一事件是否会重复通知或执行，结束条件满足后是否真正停止。

---

> **产品验收底线**
>
> “完成”必须对应一个可检查的结果——文件、日历事件、任务记录、发送记录、PR 或通知记录，而不是模型说了一句“已经帮你处理好了”。
