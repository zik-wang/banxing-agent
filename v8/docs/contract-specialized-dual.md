# 合同双模型分工

这是 Harness 编排调整，不训练或改变27B权重。旧的纯27B路径默认保留；维护者显式设置 `contractReview.collaboration.mode = "specialized-v1"` 并提供有效 `localReview` 后才启用。

本地 Qwen2.5-1.5B LoRA 只输出范围与义务、支付与财务、责任与救济三类局部风险信号；它不能提供完整合同解释、主体关系、法律结论或可靠无风险证明。

宿主先取得本地覆盖回执。完整时，27B独立主审其余专题，并保持看不到本地结果；原配置映射的三类专题转到一个专门的27B完整上下文阶段，结合原始正负信号查条件、例外、保障和语义漏报。随后保留跨条款审查与反例裁定。所有配置专题和原始片段都必须有27B处置，本地未触发不能免检。局部处理失败、未读或超时则回退完整27B主审，不减少清单。

每个原文批次的一般调用下限为：主审批数＋局部专题上下文批数＋跨条款批数＋反例批数；额外恢复仍有界。仍使用12次总模型调用上限，不以无限重试消化分歧。新增阶段占用预算，双模型不保证更快。

配置中的 `local_signal_checks` 决定分工，不在程序写死合同专题ID。运行保存collaboration、每阶段实际输入、正负局部信号、原始引用、未处理范围、候选来源与最终处置。报告中的“完成”指执行状态，不表示法律可签或零遗漏。

评价应至少区分：相同局部任务的风险分类、完整合同下的保障/例外处理、关键漏报/误报、证据定位和完整交付。纯1.5B无法完成的能力明确为未支持，不能用一项分类命中率代替整合同审查能力。若无独立人工Gold，仅可报告明确标注的合成参考结果。
