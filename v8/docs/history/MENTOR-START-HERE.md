# Mentor：从这里开始

这是可立即试用的伴行V7冻结版本，应用代码沿用v7-mentor-rc1。本次只补启动入口和真实公开材料示例，不修改09或继续扩展功能。

## 先启动

1. 获得私有仓库访问权限后，在 Releases 下载最新试用ZIP并解压。
2. 安装 Node.js 24（本轮实测版本24.15；允许22.19以上），连接公司内网。
3. Windows双击 START-WINDOWS.cmd，等待依赖安装，保持窗口打开。在浏览器打开 http://127.0.0.1:8814/ 。第一次安装需要连接npm依赖源。

这个入口使用随包提供的**无凭据公司内网连接配置**，不在电脑上加载27B模型。日历明确使用独立验证日历。运行数据单独保存在data/mentor，原件不会作为发布文件上传。

若8814被占用，不要关闭未知进程；在PowerShell执行：

```powershell
$env:PORT='8820'
node scripts/start-mentor.mjs
```

然后打开http://127.0.0.1:8820/。若内网接口不可达，页面会说明；本示例中的基本表格操作仍可执行，复杂理解和PDF等能力取决于服务连接。

## 示例：真实公开报表连续处理

新建一个对话，一次上传 examples/mentor/公开支出A.xlsx 和 公开支出B.xlsx，之后一直留在这个对话，不要反复上传。

依次输入，每一步完成后打开下载文件检查：

1. 这俩表给我合一下。
2. 重复的不要。
3. 按Amount降序排列。
4. 再给我一个领导看的版本。

预期：先得到合并表，再得到去重结果和排序结果，最后主动交付Word报告。两份输入各20条，有10条重叠；去重主明细应为30条，重复来源另表保留。Amount应按数值降序，不按字符串排序；原行和来源应保留。

这组步骤验证确定性办公操作与连续交付。想额外验证内网Qwen理解改换说法，可在同一对话再说：**按Amount的数额大小倒着排列，然后转Word**。这会进入受约束模型工具；检查执行记录，不把前面零模型调用的流程当成模型准确率。

材料来自英国DESNZ真实公开支出数据，已按明确行范围转换为Excel，无虚构业务金额。B表调整列顺序、增加来源说明；Department表头译为“部门”。原始CSV、来源链接和SHA256见本目录及sources.json。此示例不代表陌生材料盲测。

来源：https://www.gov.uk/government/publications/desnz-spending-over-25000-september-2025

## 日程目前能演示什么

另建对话，依次输入：

1. 下周找个下午开半小时会。
2. 改成一小时。
3. 核对提议卡的日期和时间，点击“确认创建”。

应先查询独立日历，确认后实际写入独立日历并回读；页面提供取消操作，再次确认后删除回读。这个日历的事件不是公司真实日程。复杂自由表达还依赖内网Qwen。

**日程安排尚未完成真实业务验收**：没有接入真实账号；参会人的忙闲、重复/全天事件、复杂多约束排程没有完成全面验收。拿到可用公司日历接口或CalDAV账号后，还需真实查询、冲突、确认写入和回读测试。不能仅提供一个不兼容平台的账号就承诺可用。
