# 助理协作与自适应 Harness

普通工具对话中，模型根据用户目标、已启用助理的职责和实际工具回执，选择自己处理或调用 `request_assistant_handoff`。主办助理、是否需要额外复核、复核人都由本次决策给出；财务→通用仅是验收用例，不是固定业务流程。用户指定复核人时必须尊重，用户说“由你复核”指当前助理。

通用网页任务默认采用宿主配置的 `executionPolicy.mode=adaptive`，移除固定模型轮数、工具/发现/视觉调用次数、续跑累计调用和整链时间预算，继续记录实际调用次数。单次网络请求超时和网络重试策略仍有效，用户可停止整条协作链。独立 CLI 通过相同配置显式启用；宿主可用 `bounded` 保留兼容模式。

主办助理可以在业务写入前再次转交给本链路尚未主办的同事。宿主阻止回到祖先助理形成转交循环，并逐级传回真实成果引用和复核回执。这个版本是整项任务转交，不是并行子任务拆分。

宿主继续校验每一份材料的授权、版本、排除状态与实际选取记录。协作不扩大文件范围，不继承同事的挂载目录、排程或额外知识库。复核只读，不改写交付；失败、分歧和缺输入如实保留。流程标为 reviewed 不等于事实已核实，不因同模型角色一致就设置 contentVerified。

`assistantRouting.enabled=false` 可停用新转交。合同审核专项和显式群组会议仍使用各自协议，本次没有将它们改成通用自适应运行；排程不主动发起自动协作。正式服务不随分支改动自动替换。

实现与测试说明见 [adaptive-harness.md](adaptive-harness.md)。离线工程测试不代表真实模型一定能正确选择助理或准确完成业务任务。
